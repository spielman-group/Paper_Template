# Agent Workflow Guide

This directory (`AGENTS/`) and the hidden `.agents/` directory contain the structure and state for automated AI assistants (agents) collaborating on this manuscript. This document explains the architecture and how to use the available agent skills.

## Architecture Overview

To keep the repository clean and maintain a clear separation between instructions and generated context, the agent workflow is divided into three parts:

1. **`AGENTS.md` (Root Directory)**: The "Constitution." This file contains the mandatory operating rules, result integrity guidelines, and a high-level directory of available agent skills.
2. **`.agents/skills/` (Hidden Directory)**: The "Logic." This contains individual folders for each agent role (e.g., `colleague`, `coauthor`). Each folder contains a `SKILL.md` (the prompt/instructions) and any templates needed for that skill.
3. **`AGENTS/` (Visible Directory)**: The "State." This directory holds the artifacts and state files generated by the agents (e.g., `RESULTS.md`, `PI_STRUCTURE.md`, `REFEREE_REPORT_1.md`). Keeping these visible allows human authors to read, verify, and edit the agent's "shared understanding" of the project.

## The Shared State: `RESULTS.md`

The core of the workflow is the `AGENTS/RESULTS.md` file. It serves as the shared scientific context between different agent roles. It contains:
- Paper Summary
- Core Scientific Claims
- Open Questions & Weaknesses
- Target Venue
- Structural Outline / Figure Mapping

**Note on Dependencies:** Skills are designed to be invoked in any order. If you invoke a skill that requires `RESULTS.md` (like `coauthor`) but the file does not exist, the agent will automatically spawn a non-interactive subagent to run the `colleague` skill and generate the file. This prevents the main agent's context window from being flooded.

## Available Agent Roles (Skills)

* **`colleague`**: Acts as a sounding board for scientific feedback, new ideas, and literature searches. It does not edit the LaTeX source. It discusses the paper with you and outputs/updates `AGENTS/RESULTS.md` to reflect your shared understanding.
* **`coauthor`**: Helps write and refine the manuscript paragraph-by-paragraph. This role is a 50/50 split between scientific feedback and writing. It edits the LaTeX source directly using the `\agentedit` and `\agent` macros. It relies heavily on `AGENTS/RESULTS.md` and updates it as the paper evolves.
* **`pi_structure`**: Non-interactive role that reads the entire paper and attempts to describe the scientific argument paragraph-by-paragraph. It compares the draft against `AGENTS/RESULTS.md` to flag misalignments and outputs `AGENTS/PI_STRUCTURE.md` with suggested structural changes.
* **`pi_revision`**: Reads the entire paper and marks it up from beginning to end using LaTeX macros. Before starting, the agent will ask you for the desired level of detail (e.g., direct edits vs. comments only).
* **`editor`**: Simulates a journal editor deciding whether to send the paper out for review based on the manuscript and a cover letter. It outputs `AGENTS/EDITOR.md` with a frank explanation of the decision.
* **`reviewer`**: Simulates a blind peer review. This agent does *not* have access to `AGENTS/RESULTS.md`. It reads the manuscript and produces `AGENTS/REFEREE_REPORT_1.md`. A subagent will then compare the report against `RESULTS.md` to generate `AGENTS/REFEREE_MISCONCEPTIONS_1.md`.
* **`bibliography`**: Cleans the BibTeX file, adds new references, and validates existing citations. It safely refactors citation keys across linked `.tex` files.
* **`paper-template-style` & `latex-build`**: Utility skills focused on project hygiene, formatting, and compiling the LaTeX document to ensure reproducibility.
